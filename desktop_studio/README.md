# Hairwork Studio (desktop)

Native Windows (C++ / DirectX 11 / Dear ImGui) successor of the web Groom Studio, part of Hairwork for All. Hair is rendered and **simulated by the real
NVIDIA HairWorks 1.2.1 runtime**: gravity, stiffness and its curves, damping, mass, inertia limit, back-stop, collision
capsules, wind, density map, LOD. Start it with `Launch_Groom_Studio_Desktop.bat` (repo root). The web Studio
(`Launch_Groom_Studio.bat`) is unchanged.

## How it works

```
desktop_studio\tools\desk_prep.py <cfg>
   -> current build: build\desktop_studio\furs\<cfg>__<comp>.redfur (+ <cfg>.src.json stamp) + build\hairbatch\edit\<cfg>.json
      (hairpipe.build(assemble=True) when the stamp's hash of the config + edits file differs; nothing installed)
   -> build\desktop_studio\<cfg>\desk.json (+ tex_*.png)
Hairwork Studio (desktop)  (HairWorks asset + instance from desk.json; edits = ops on the edit-frame guides)
Export  ->  build\desktop_studio\<cfg>\export\: <char>_<tag>_edits.json, _look.json, _geo.json, _config.json,
            <mod>\content\blob0.bundle + metadata.store, <mod>_<tag>.zip   (desk_export.py; nothing is installed)
```

- **Which build.** The pack always reads the config's CURRENT pipeline build, never a lab round copy
  (`build\hairlab\<round>\furs` are snapshots of older pipeline / config states: the L124 copy of
  `guillaume_l124_locks_hug` was 5 mm median / 29 mm p99 off the shipped fur). `desk_prep.py` keeps
  `build\desktop_studio\furs\<cfg>__<comp>.redfur` with a stamp (sha1 of `chars\<cfg>.json` + its edits file) and rebuilds
  it when the hash changes (`--build` forces it). The Studio re-preps a pack when its `prep_version` is old, a source
  file (`desk.json src_files`) is newer than `desk.json` or its fur is gone (`app.cpp packUpToDate`; same test:
  `desk_prep.py <cfg> --check`). Checked 2026-10-11: the rebuilds of every approved config (Guillaume, c04ma, Regis,
  Dandelion, Triss, Keira) are byte-identical to `mods\mod<Char>Hairworks`; `vesemir_l232_mirror_ear_back` equals its
  L232 round fur (the shipped Vesemir mod is still `vesemir_r31a`, also byte-identical to its rebuild).
- **Loading** starts from the character's OWN built redfur: guides, growth faces, per-corner UVs, per-guide bone indices
  / weights, bind poses, bone parents, collision spheres + capsules, and the full physical / graphical / LOD blocks, mapped
  1:1 onto `AssetDescriptor` / `InstanceDescriptor` (`src/hairsdk.cpp updateDescriptor`). Positions stay in the game's
  metres (`m_sceneUnit` 100, Z up). The density texture (with its channel) and the card colour texture, when the fur uses
  one, are bound as HairWorks control textures. LOD is always on.
- **Emulated (not in this runtime):** the W3-only `stiffnessBone*` (bone-distance stiffness) block. Without it the
  1.2.1 solver lets curls stretch and the ends drop ~1.7 cm below the game (measured on L237, see "Simulation vs game").
  For furs with `stiffnessBoneEnable` the app raises the SDK's stiffness / stiffness-strength / bend-stiffness curves
  towards 1 with weights `amount x stiffnessBoneCurve` and bendStiffness towards 1 by `amount` (`src/hairsdk.cpp`).
  Preview only: look values and exports are untouched. Physics panel slider "W3 bone stiffness" (default 1, right-click
  resets, 0 = raw runtime), agent `{"do": "bone_stiffness", "amount": 0..1}`, env `HW_BONE_STIFF_EMU`.
- **Runtime quirk:** `createAsset` with more than one collision sphere crashes this 2016 DLL in
  `updateSkinningMatrices`. The app therefore serialises the created asset with the SDK's own `saveAsset` (binary .apb,
  in memory) and loads it back with `loadAsset`, which works (`HW_DIRECT_ASSET=1` skips the round trip).
- **Motion presets** (`src/motion.cpp`): rest, idle, turn head, nod, walk bob, run, spin body, wind. They move the head /
  neck / body bones; HairWorks gets them as skinning matrices, so inertia, sag and swing show as in game.
- **Edits** (`src/groom.cpp`): the same ops as `tools/hairworks/strand_edits.py` and the web Studio (translate,
  set_point, shorten, delete, duplicate, mirror), recorded in the edit frame and matched by root (4 mm). Curl / roll /
  wave are exported **baked** as `reshape` ops (absolute points; an opt-in op added to `strand_edits.py` 2026-10-10, only
  present in edit files that use it). `strand_edits.py check <edits> build\hairbatch\edit\<cfg>.json` replays them.
- **Export** writes only what changed: geometry only when there are ops, look values only when they differ from the build
  (CR2W types taken from the fur), into the build's own redfur. Physics, LOD, density mask and collision are kept
  (unlike the web exporter's old fur02 template). The `_config.json` is a pipeline config proposal (`edits` +
  `look.extra_set`): rename it to a new `<char>_l<round>_<tag>` and copy the edits file to `tools\hairworks\edits\` to
  build it with hairlab. Approved configs are never touched.
- **Export for release (requires Core)** (Export panel, under the dev export; agent `{"do": "export", "release": true}`):
  the same export through `desk_export.py --release`: the same redfur and textures as the dev export (self-contained),
  plus `content\scripts\local\hwfa_req_<mod>_<crc>.ws`, a script that calls the Hairwork for All – Core's functions
  (`HairworkForAllCore_Required_GetItFromNexus13996()` and `HairworkForAllCore_v1_0()`), `REQUIREMENTS.txt`,
  `hairworkforall_mod.json` (`requires_core`) and the requirement line in `INSTALL_INSTRUCTIONS.txt`; the config
  proposal gets `"core": true`. The game will refuse to start without the Core: its script compiler reports the missing
  function, whose name points at https://www.nexusmods.com/witcher3/mods/13996. The Studio detects the Core by
  `<game>\mods\mod0000HairworkForAllCore\content\scripts\local\hairworkforall_core.ws` + `version.json` (every 5 s) and
  compares it with the repo's `CORE_VERSION` (`core/hwcore.py`): status bar cell "Core v1.0.0" / "Core missing" /
  "Core v<x> < <required>" / "Core incomplete (no script / version.json)" (warning colour
  unless OK) and the same line in the Export panel. A release export still works without the Core installed (only
  testing it in game needs it). See `core/README.md`. Second listed requirement (2026-10-11): Graphics Control
  (Nexus) with PT hair > 'Hair root transparency mode' = 0 (path-traced hair shows see-through gaps in mode 1), in
  REQUIREMENTS.txt, hairworkforall_mod.json (`requires`), INSTALL_INSTRUCTIONS.txt and a note under the release button.

## Performance budget (always enforced)

Hair count estimate = 64 hairs x density x sum of the per-face density-map means (x detailLODDensity for close-ups); cost
= close-up hairs x CVs per hair x width. The reference is the character's approved build (APPROVED.json), else the loaded
build. Hard caps: density <= 1.2 x reference, close-up density <= min(1.2 x reference, 2), width <= 1.5 x reference, LOD
forced on. Export is blocked above 120 % (UI button disabled, the exporter refuses too). The live SDK count
(`computeStats`) is shown next to it.

### Beard mode (2026-10-14)

Builds with a beard fur (Zoltan `zoltan_l292_b`, Lambert beard configs) show **EDITING  Hair | Beard** in the inspector,
right under the character card (also Edit > "Edit the beard fur"). In Beard mode the beard is the edited groom: every
tool, material / look / physics value, stiffness paint, check and the budget card act on it, and the hair is the preview
(the other way round in Hair mode). Each fur has its own ops, undo history and look. Implementation: `App::swapFur`
exchanges the live fur (`pack` fur fields, `groom`, `look`, `hw`, per-fur textures in `FurSlot`) with the parked one, so
the tools need no change; the head / body meshes, cameras and motion pivots (`skel`) stay the hair pack's. Projects store
the beard under `beard` (old projects load unchanged) and `"fur": "beard"` when saved in Beard mode. Export writes the
beard edits into the build's beard redfur (`desk_export.py --beard-edits/--beard-look/--beard-geo`, see
`docs/AGENT_GUIDE.md` Export). Not exported: the beard stiffness map. MCP / agent: `studio_fur` / step `fur`.

### Guide views (2026-10-14)

Two filters for the guide overlay, next to the guides button in the top bar (layers icon, person icon) and in View:
**Guides: front layer only** (Shift+G) shows only guides that are not hidden behind other hair from the current camera
(the outer layer), **Guides: hide behind the body** (Ctrl+G) leaves out the guide parts behind the head, body and
clothes. They combine, follow the camera live, and work in Hair and Beard mode. View > Guide view options: **Select
visible only** (on by default: brush, box and click select only shown guides and points), **front points %** (default 50:
share of a guide's body-visible points that must be in the front layer) and **depth tolerance mm** (default 12), plus
the count of shown guides and the cost. Selected guides are always drawn.

Internals (`src/guidevis.cpp`): two CPU depth buffers (longest side 384 px), one from the posed opaque meshes, one from
the guide segments splatted as small cones (2.5 mm); a point is body-visible when it is not behind the mesh depth (+4 mm),
front when it is within the tolerance of the nearest hair / body depth. Rasterisation is split over up to 8 threads; in the
viewport it runs on a background worker (results lag 1-2 frames) and is skipped when camera, pose and guides are
unchanged. Yennefer (2182 guides, 40k body triangles): about 4 ms on the worker, 0.6 ms on the main thread, 60 fps kept.
MCP / serve: `studio_guide_view` / `guide_view`, render keys `guides_front` / `guides_body` (see `docs/AGENT_GUIDE.md`).

## Rendering (physically based sun + sky, 2026-10-11)

The game (W3 5.0) draws HairWorks hair path-traced (PTHairQualityMode 3): real sun shadows, hair self-shadowing, sky
and bounce light, soft occlusion. The Studio approximates that in real time on DX11 with the HairWorks 1.2.1 runtime.
Meshes (`shaders/basic.hlsl`) and hair (`shaders/hair_ps.hlsl`, our own strand shader on the SDK's custom-shader
interface) share one light rig (`shaders/studio_light.hlsli`, `src/lighting.cpp`, `drawScene` in `src/app.cpp`):

- **Units and sky.** Light values are irradiance / pi (a white Lambert surface facing the sun shows `sun`). The sky is
  procedural (no image assets): zenith colour, a horizon band (trees / haze), a small circumsolar glow, and a ground
  whose radiance is its albedo x (sun + sky light), so the bounce from below follows the sun. It is projected every
  frame to SH9 irradiance (48 x 96 samples on the CPU) and also gives a sky / horizon / ground lookup for reflections.
- **Sun shadow.** One 2048 orthographic map (2.3 m around head and shoulders) with the meshes and the hair (SDK shadow
  pass, `ShaderSettings(shadowPass)`, density x shadowDensityScale). Meshes: contact-hardening soft shadow (blocker
  search, then a 16-tap rotated Poisson PCF whose radius = blocker distance x tan(sun size)). Hair: the SDK's deep-shadow
  filter (`NvHair_ShadowFilterDepth`, gathered penetration depth behind the first occluder), transmittance
  exp(-depth / (shadowSigma x Hair depth)): hair shadows itself, the head and body shadow the hair, the hair shadows
  the skin.
- **Sky occlusion.** 8 / 16 orthographic depth maps (1024, 1.5 m box around the head) seen from fixed sky directions
  (12 over the sky + 4 from below for 16), holding meshes and hair. Meshes: per direction 4 texels compared, weighted by
  sky radiance x the cosine lobe = soft ambient occlusion (eye sockets, under the chin, hair over the forehead / neck).
  Hair: the same deep-shadow transmittance per direction (sky light goes deeper: 3 x sigma) = self-occlusion inside the
  groom (dark recesses between curls). The viewport refreshes 4 maps a frame (all 16 every 4th frame: the maps are
  fixed in the head frame); shots refresh all of them.
- **Hair shading.** Diffuse = the SDK reference model lerp(strand Kajiya term, Lambert on the hair-volume normal,
  diffuseBlend) x the sun transmittance; ambient = SH(hair-volume normal) x sky visibility x (0.5 + ambientEnvScale).
  Specular Kajiya-Kay primary (per-strand breakup) + secondary (tinted) x sun transmittance; a Marschner-style
  transmission lobe (TT, "Back light") for back-lit light hair. **Colour**: redfur colours / card textures are decoded
  with a partial gamma (`hair_encoding` 0.7: 0 = sRGB-decoded, 1 = the stored 8-bit value), then multiple scattering
  saturates them: diffuse colour = colour x hue^k, k = 1.0 for sun light ("Hair scattering") and 0.4 for sky light.
  Fitted on Guillaume (sun-lit gold, olive shade), Vesemir (silver-grey) and the near-black L246beard Lambert beard:
  the fully stored-value reading (1) made dark hair far too light, the sRGB decode (0) gave Guillaume's old
  over-saturated yellow.
- **Skin / eyes / mouth** (class from the pack's textures: head and `g_*` body = skin, `*eye*` = eyeball, teeth /
  tongue = mouth): skin has a wrapped (subsurface) diffuse with more wrap for red, a red-bleeding shadow edge, a GGX
  lobe (roughness 0.42, F0 0.028) and redder ambient; eyeballs get a sharp wet highlight and lid occlusion (the lids /
  lashes are not drawn); the mouth is occluded. Cloth / leather / metal: Lambert + GGX (0.65) + sky reflection.
- **Beards (2026-10-11).** The vanilla beard / moustache cards of the appearance (desk.json `beard_cards`, written by
  `desk_prep.py`; PREP_VERSION 6 re-preps older packs) are drawn alpha-tested with alpha to coverage (MSAA), shaded as
  soft strand cards (card albedo x 0.55, the game's hair shader darkens them), and cast shadow / sky occlusion through
  an alpha-tested depth shader (`ps_depth_alpha`). A beard config's `beard_fur` (`<cfg>__hb_*.redfur`) is a second
  HairWorks instance (`App::hwBeard`, its own SDK object from the same DLL; preview only: not editable, not in the
  budget, not in the mask pass): it is skinned to the head / neck / body, simulated, shadowed and rendered with the same
  shader and its own material values, and the vanilla cards are hidden when it is present, as in game.
- **Tone curve.** ACES RRT + ODT fit (sRGB) after exposure, into an sRGB target (`tone` 1 = the same curve on luminance).

**HairLab capture rig (preset 0)**, fitted on round L244 (approved Guillaume `guillaume_l124_locks_hug`, path-traced,
`results/L244ctl`) and L232 (`vesemir_l232_mirror_ear_back`) at the HairLab cameras, with `tools/lookcompare.py`
(in-game | before | after sheets + hair / face statistics), parameter sweeps through the agent `rig` step and a
whole-frame check by eye (hair, face, armour, leather): sun from behind the character (azimuth -160 deg, elevation 46
deg, 2.2, warm white), sky 1.9 (pale blue), horizon 1.1 (green: the trees), ground 0.7 (warm dirt road), exposure

## Posed editing / edit pose

The guide overlay, picking, box select and brushes use the CURRENT skinned pose (guide rest points x the bone matrices
HairWorks gets), so they sit on the hair you see. An editing tool (Move, Comb, Curl, Paint) enters **Edit pose**: the
motion pauses, the character goes back to the bind pose and the hair to rest; "Resume motion" (or the Select tool) restores
the preset. "Edit while moving" keeps the motion; every drag / comb offset is then converted from posed to rest space
(inverse of the guide's dominant bone matrix) before it is stored, so the ops stay valid for the pipeline. Verified: a
Move during "Spin body" exported `offset [0, .0242, 0]` in rest space and `strand_edits.py check` replays it with 0
unmatched.
