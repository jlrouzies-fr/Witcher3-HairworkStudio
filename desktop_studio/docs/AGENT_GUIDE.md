# Hairwork Studio: guide for AI agents

How to drive the desktop Studio (`desktop_studio/`) without a human: headless agent scripts, UI test scripts, packs, exports. Everything here is checked against the code (`src/main.cpp`, `src/agent.cpp`, `src/uitest.cpp`, `tools/desk_prep.py`, `tools/desk_export.py`). The human manual is `docs/guide/guide.html`. Read `AGENTS.md` (hard rules) first, then `desktop_studio/README.md` for internals.

## Hard rules for Studio work

1. **No real input, ever.** Never use SendInput, pywinauto, AutoHotkey, screen clicking, `SetForegroundWindow` or any OS-level mouse / keyboard / focus. Drive the UI only with `--ui-test` (events injected into Dear ImGui) or the headless `--agent` runner. A normal launch takes the user's screen; a ui-test run opens the window **without activation, off the visible desktop** (`main.cpp`).
2. **No game runs** unless the task says so. The Studio needs no game process. Never kill a `witcher3.exe` you did not start.
3. **Approved builds are frozen** (`tools/hairworks/APPROVED.json`): rebuilding one must give byte-identical output. New generator behaviour is an **opt-in config key** and never a default. A shared-code fix gets a legacy switch set in approved configs. The Studio itself never touches approved configs: its export writes a *proposal* (`<char>_<tag>_config.json`); a new variant needs a new name `<char>_l<round>_<tag>`.
4. **NVIDIA SDK material never enters git** (`sources/` is git-ignored; `py tools/sdk_guard.py --tracked` and the `.githooks/pre-commit` hook enforce it; run `git config core.hooksPath .githooks` once per clone). Do not paste SDK headers or docs anywhere. Only the runtime DLL ships in release packaging.
5. Do not edit `desktop_studio/packaging/` or release settings unless that is your task; commit messages carry no model identifier except the trailer the session gives you.
6. Never overwrite another agent's work: re-read a file before editing; keep `build/` and `results/` out of git.

## Build and launch

| What | Command (repo root) |
|---|---|
| Build if missing or stale, then run | `Launch_Groom_Studio_Desktop.bat` |
| Force a rebuild | `Launch_Groom_Studio_Desktop.bat --rebuild` |
| Manual build | `cmake -S desktop_studio -B desktop_studio/build -G "Visual Studio 17 2022" -A x64 [-DHAIRWORKS_SDK_DIR=<sdk>]` then `cmake --build desktop_studio/build --config Release` |
| The exe | `desktop_studio\build\Release\HairworkStudio.exe` (shaders `*.cso` and `assets\` sit next to it) |

The .bat rebuilds when the exe is missing or any file in `src/`, `shaders/`, `CMakeLists.txt` is newer than it, passes its first 9 arguments to the exe, waits for the window to close and prints the last 15 log lines on a crash (`CRASH` line = function + source line). It `pause`s on a crash or build failure: when running from an agent call the exe directly so nothing blocks. Do not run two builds in the same `desktop_studio/build` at once.

Needs: VS 2022 Build Tools (C++ workload, Windows SDK), CMake >= 3.20, the HairWorks 1.2.1 SDK in `sources/HairWorks-r1_2_1-15-distro/HairWorks` (or `HAIRWORKS_SDK_DIR`), Python (`py`) with `requirements.txt` installed.

**Python.** A dev build calls the pipeline through the `py` launcher (Settings > Python). A release folder carries its own private CPython 3.13 (`python\python.exe` next to the exe, with numpy / Pillow / scipy / lz4 in `python\Lib\site-packages`; made by `desktop_studio/packaging/embedded_python.py` during `package_release.py`, downloads cached in `build/python_embed/`, SHA-256 pinned): the exe uses it by default when it exists, so players need no Python. A saved Settings value other than `py` / empty overrides it. The bundled `python313._pth` puts the release root, `tools`, `tools\hairworks`, `desktop_studio	ools` and `core` on `sys.path`. To run a pipeline script by hand in a release folder use `python\python.exe <script>`. Do not commit the runtime (`build/` is git-ignored; the public export leaves it out).

## Command line

Parsed in `main.cpp parseArgs`:

| Flag | Meaning |
|---|---|
| `--agent <script.json>` | Headless runner (no window shown, console output, log `build\desktop_studio\agent.log`) |
| `--ui-test <script.json>` | Scripted UI run (log `build\desktop_studio\desktop_studio.log`) |
| `--cfg <cfg>` | Open this build at start |
| `--project <file>` | Open a `*.groomproj.json` at start |
| `--sdk <dir>` / `--dll <path>` | HairWorks SDK folder / DLL (override Settings) |
| `--screenshot <png> --frames N [--exit]` | Save the back buffer at frame N (default 240); `--exit` closes after |
| `--view front\|back\|left\|right\|34\|back34`, `--motion <prefix>`, `--guides`, `--close-lod` | Initial camera / motion / overlays |
| `--no-splash` | Skip the splash |
| `--guides-front`, `--guides-body` | Guide views on at start (front layer only / hide behind the body); both also switch the guide overlay on |

Environment: `GROOM_STUDIO_NOACTIVATE=1` (window opens without activation off-screen; always on for `--ui-test`), `HAIRWORKS_SDK_DIR`, `HW_DIRECT_ASSET=1` (skip the save/load asset round trip), `HW_BONE_STIFF_EMU` (bone-stiffness emulation strength). Settings file: `%LOCALAPPDATA%\HairworkForAll\desktop_studio.json`.

Exit codes of `--agent`: 0 ok, 2 script unreadable, 3 HairWorks runtime not loaded, 4 cannot open the build or project, 5 unknown material preset, 6 export blocked or failed, 7 unknown step.

## Making a pack (`desk_prep.py`)

The Studio opens a **pack** (`build\desktop_studio\<cfg>\desk.json` + `tex_*.png`). The Studio runs the prep itself when needed (`openConfig(cfg, reprep)`); by hand:

```
py desktop_studio\tools\desk_prep.py <cfg>            # build/refresh the pack (builds the fur when the config hash changed)
py desktop_studio\tools\desk_prep.py <cfg> --build    # force a pipeline rebuild of the fur first (nothing installed)
py desktop_studio\tools\desk_prep.py <cfg> --check    # prints 'current' (exit 0) or the reason it is stale (exit 1)
py desktop_studio\tools\desk_prep.py --list           # configs with a built fur; '*' = approved
py desktop_studio\tools\desk_prep.py --catalog        # character catalog JSON for the picker
```

Rules:
- The pack always reads the config's **current** pipeline build (`build\desktop_studio\furs\<cfg>__<comp>.redfur` + a `<cfg>.src.json` stamp: sha1 of `chars\<cfg>.json` and its edits file), never a lab round copy.
- A pack is stale when `prep_version` (`PREP_VERSION` in `desk_prep.py`, `kPrepVersion` in `src/app.cpp`) is older, a source file listed in `desk.json src_files` is newer, or its fur is gone. Bump both constants when `desk.json` changes shape.
- Prepping and exporting install nothing into `<game>\mods`.

## Agent scripts (`--agent`)

```
desktop_studio\build\Release\HairworkStudio.exe --agent script.json
```

The runner loads the build (`cfg`, optional `"reprep": true`) or a project (`"project": "<path>"`), settles the simulation at rest, then runs `steps` in order. Top-level keys: `cfg`, `reprep`, `project`, `out` (default `build\desktop_studio\agent`), `steps`.

```json
{"cfg": "guillaume_l124_locks_hug", "out": "C:/tmp/run1",
 "steps": [
  {"do": "ops", "file": "tools/hairworks/edits/guillaume_user1.json"},
  {"do": "select", "where": {"back": true, "z_min": -0.03}},
  {"do": "delete"}, {"do": "shorten", "where": {"back": true}, "keep": 0.8}, {"do": "duplicate", "step_mm": 6},
  {"do": "curl", "where": {"back": true, "tip_below": 0.15},
   "params": {"mode": "roll", "start": 0.6, "radius": 0.015, "turns": 1.2, "shrink": 0.6, "band": false}},
  {"do": "material", "name": "Fine strands (Yen", "keep_colours": true},
  {"do": "look", "set": {"physicalMaterials.stiffness.tipStiffness": 0.4}},
  {"do": "hold_curls"},
  {"do": "stiffness", "where": {"front": true}, "s": 0.9, "r": 1.0},
  {"do": "rig", "tod": 0, "sun": 2.0, "shadows": true, "quality": 2},
  {"do": "motion", "preset": "walk", "seconds": 3, "speed": 1, "amount": 1, "reset": true},
  {"do": "settle", "seconds": 2},
  {"do": "shots", "tag": "v1", "shots": [0, 2, 3, 4, 5, 15], "pair": true, "mask": false, "size": 1400},
  {"do": "bench", "w": 2560, "h": 1440, "frames": 240, "quality": 2, "view": "34", "preset": "idle"},
  {"do": "save_project", "path": "C:/tmp/run1/x.groomproj.json"},
  {"do": "export", "tag": "agent1", "mod": "modGuillaumeHairworks", "release": false}]}
```

Step reference (all from `agent.cpp`):

| `do` | Keys | Notes |
|---|---|---|
| `ops` | `file` (an edits JSON with `ops`) or `ops` (inline list) | appends ops, replays, reports `unmatched` roots (4 mm match) |
| `select` | `where` | sets the selection |
| `curl` | `params`, optional `where` | `params` = `CurlParams` JSON (`mode` ringlet / roll / wave, `start`, `radius`, `turns`, `ramp`, `hand`, `jitter`, `shrink`, `side`, `band`, `zigzag`); reports `cvs_per_turn` and a warning under 6 |
| `delete` / `shorten` / `duplicate` | `where`, `keep` (0..1, default 0.8), `step_mm` (default 6) | without `where` uses the current selection |
| `material` | `name` (prefix match of a preset name), `keep_colours` (default true) | exit code 5 and `error` when no preset matches |
| `look` | `set` {param path: number or JSON} | param paths as in `src/params.cpp` (e.g. `graphicalMaterials.color.rootColor`); caps are re-enforced |
| `hold_curls` | | raises stiffness / flattens curves for held curls |
| `stiffness` | `where` (default all), `s`, `r` | per-guide stiffness map values |
| `rig` | `tod` (0..8), `sun`, `sky`, `exposure`, `colour_gain`, `spec_gain`, `spec_power`, `tex_gain`, `self_shadow`, `floor`, `sun_az`, `sun_el`, `shadows`, `horizon`, `ground`, `quality` (0 fast, 1 balanced, 2 high), `ao`, `tone`, `sun_size`, `shadow_soft`, `sun_col` / `sky_col` / `horizon_col` / `ground_col` ([r,g,b]), `debug`, ... | `tod` is applied first, explicit keys override it |
| `motion` | `preset` (prefix: idle, walk, run, turn, nod, spin, wind, rest), `seconds` (2), `speed`, `amount`, `reset` | runs the simulation for `seconds` at 60 Hz |
| `settle` | `seconds` | rest pose, then simulate |
| `simulate` | `on` | false = hair on the skinned rest shape |
| `bone_stiffness` | `amount` 0..1 | W3 stiffnessBone emulation (preview) |
| `shots` | `tag`, `shots` (default `[0,2,3,4,5,15]`), `size` (1400), `pair` (true), `mask` (false) | HairLab cameras from the pack; writes `<tag>_shot<n>.png`, `<tag>_<view>_PAIR.png` (vanilla left, ours right) when a vanilla still exists, `<tag>_shot<n>_mask.png` (flat-red hair-only pass) |
| `scalp_coverage` | `shot` or `shots` (default 3), `size` (1400), `tag`, optional `rect` [x0, y0, x1, y1] | renders each shot with the scalp overlay, counts pure-ish green pixels (g>200, r<60, b<60) and reports `scalp_pixels` (whole image) and `scalp_pixels_in_rect`; writes `<tag>_shot<n>_scalp.png` (lit overlay image) and `<tag>_shot<n>_scalp_mask.png` (white = scalp) |
| `pick` | `shot`, `x`, `y` (pixels of the `size` image, default 1400) or `auto: "scalp"` (+ optional `rect`: the green pixel nearest the centroid of the visible scalp), `n` (guides listed, 6), `tag` | what is under the pixel: `top` (`hair` from the hair-only mask pass, else `scalp`, else `background_or_outfit`), `hair_over_skin`, `scalp_world` (ray cast on the posed skin meshes, same pose as the render), `face` (growth face `id` = index in the current faces, its 3 guide ids, `bary`, `inside`), `nearest_guides_by_root` (posed root distance to the scalp point, mm), `nearest_guides_on_screen` (guides whose posed strand passes closest to the pixel, px; `edited` flags guides touched by ops); writes `<tag>_shot<n>_pick.png` (overlay + magenta crosshair) and `_pick_plain.png` |
| `bench` | `w`, `h`, `frames`, `quality`, `view`, `preset` | GPU-synced frame time of the viewport scene: `ms_median`, `ms_p95`, `fps_median`; writes `bench_q<quality>.png` |
| `dump_params` | `path` | every fur value next to the SDK instance value |
| `save_project` | `path` | `*.groomproj.json` |
| `export` | `tag`, `mod`, `release` | see Export below; `release: true` adds the Core check info (`core`: installed, version, required) |
| `apply_pack` | `dir` (a pack folder with pack.json + edits.hwgroom) | applies a community pack on the loaded project like Community > Apply (ops, baked geometry, look `params`); returns `message` and `unmatched` |
| `dump_geo` | `path` | writes the current groom (alive guides with all points, faces by alive index + per-corner uv) as JSON; `tools/community_bake.py compare` checks it against a build |
| `report` | | no-op (the budget is attached to every step anyway) |
| `fur` | `fur`: `beard` or `hair` | Beard mode: makes that fur the edited one (every later step, check and the budget act on it; the other fur is the preview). Returns `fur`, `has_beard`, `comp`, `guides`, `faces`, `ops`; error when the build has no beard fur, exit code 7 for another value |

**Scalp highlight.** `{"do": "rig", "overlay": "scalp"}` (any `"overlay"` other than `"scalp"` switches it off) or `"overlay": "scalp"` inside a `shots` step makes the head / body skin (not eyes, teeth, beard cards, outfit) flat unlit pure green (0,255,0): `basic.hlsl ps_mesh` returns it before lighting, shadow and tonemap, hair renders normally. In the UI: View > Scalp highlight (green). Off = default render, nothing changes. Typical run: `{"do":"scalp_coverage","shots":[3,15],"rect":[480,260,760,380]}` then `{"do":"pick","shot":15,"auto":"scalp","rect":[480,260,760,380]}`. Note the face skin is green too, so use `rect` to count only the region of interest (crown patch, hairline). Hair simulation is not bit-deterministic: two identical runs differ by a few thousand edge pixels, so compare coverage numbers with a tolerance of roughly 1 %.

`where` selectors (root-based, edit frame): `all`, `back` / `front` (vs head centre y), `left` (+x) / `right`, `z_min` / `z_max` (m, relative to head top), `tip_below` (m), `roots` (list), `indices`.

Outputs in `out`: `report.json` (per step result plus `budget`: `hairs`, `hairs_close`, `ref`, `ref_hairs_close`, `ratio`, `over_limit`; final block with `config`, `guides`, `faces`, `ops`, `unmatched`, `hairs_live`, budget, `material`, `look_changes`, `stiffness_map`) and `edits.json` (the resulting edit ops). Unknown step: `error` and exit code 7.

Shots: the character's own raw cameras are used when a round exists (`results/*/raw`), otherwise the generic Guillaume rig; 1400 px by default, camera and `fovy` taken from each shot's JSON in the pack.

Calibration helpers: `py desktop_studio\tools\calib.py <cfg> <out> <tag> --sheet sheet.jpg` (needs `mask: true`), `lookcompare.py`.

## UI test scripts (`--ui-test`)

```
desktop_studio\build\Release\HairworkStudio.exe --ui-test script.json
```

Events go straight into ImGui (`AddMousePosEvent`, `AddMouseButtonEvent`, `AddKeyEvent`): the OS cursor, keyboard and focus are never touched. Widgets are found **by label** using ImGui's test-engine item hooks. The splash is off unless the script sets `"splash": true`. Time is fixed at 1/60 s per frame. After the last step the app closes itself and writes `<out>\ui_test_result.json` (`steps` with `ok` / `note`, `failures`, `crash`). Check it: a failed step does not abort the run.

Top level: `{"out": "<dir>" (default build\desktop_studio\uitest), "splash": false, "steps": [...]}`. Screenshots are the back buffer at the window's size (about 3334 x 1969 on a 4K screen).

Steps (`uitest.cpp`):

| `do` | Keys |
|---|---|
| `click` / `dclick` / `rclick` | `label` (+ `nth`, 0-based among identical labels) or `xy` [x, y] in pixels; optional `rows` (n widget rows below the label), `dx` (x offset). Waits up to 60 frames for the widget to appear, then fails with `widget not found` |
| `hover` | `label` / `xy`, `dx` (tooltips, hover states) |
| `move` | `xy` |
| `drag` | `xy` -> `to`, `button` (0 left, 1 right) |
| `wheel` | `xy`, `dy` |
| `key` | `key` (A-Z, 0-9, F1, F6, F12, Space, Escape, Enter, Delete, Tab, Period), `ctrl`, `shift` |
| `text` | `text` (typed characters) |
| `wait` | `frames` (default 30) |
| `wait_job` | `max_frames` (3600): waits for a background load / build |
| `shot` | `name` (PNG saved to `out`) |
| `expect` | any of: `loaded`, `config`, `picker`, `simulate`, `ops`, `motion` (prefix), `material` (prefix), `widget` (label visible), `tod`, `shadows`, `paused`, `tool` (0 select, 1 move, 2 comb, 3 curl, 4 paint), `editpose`, `hairdebug`, `light`, `camshot`, `symmetry`, `guides`, `exported`, `collapsed`, `style`, `loaded_style`, `editor_style`, `guides_front`, `guides_body` (bools), `selected_min` / `selected_max` (selected guide count), `selected_shown` (true = every selected guide is in the visible set) |
| `list_widgets` | writes `<out>\widgets.json`, every label seen in the last frame (use it to find labels) |

Any step may add `then_wait` (frames to wait afterwards, default 2).

Label conventions: section headers by name (`Material`, `Look`, `Physics and motion`, `Stiffness map`, `Curl tools`, `Symmetry`, `Edit settings`, `Export`); slider rows by parameter label (`stiffness`, `root stiffness`); rail `##sel ##mov ##comb ##curl ##paint ##sym ##undo ##redo ##dup ##short ##del ##shortcuts ##settings`; top bar `##tb_guides ##tb_gfront ##tb_gbody ##tb_hair ##tb_coll ##tb_bones ##tb_wire ##tb_plane Front##tb_cam4 ¾##tb_cam3 Side##tb_cam2 Back##tb_cam0 ##tb_frame ##tb_tod ##tb_shadow ##tb_collapse`; bottom bar `##tb_play ##tb_stop ##tb_step ##tb_motion ##tb_wind`; title bar `File Edit View Help ##crumb ##crumb_style Characters##chars Export mod##title`; picker `card` (use `nth`), `##q` (search box), `Open##drawer`, `##drawer_close`, `All##st`..`Not started##st`, `Painted##pt`, `<type>##ht`, `<part>##gp`, `<style>##style`; popups `Close##settings`, `Close##shortcuts`, `Close##about`, `Advanced...##light`.

Gotchas learned from running it:
- Clicking outside an open popup only closes it; click again.
- The inspector clips sections below the fold, and widgets that are not drawn cannot be found: collapse open sections (Material, Export) first, or scroll with `wheel`.
- Mouse position matters for tooltips: `move` to a blank area (for example `[1400, 700]` in the picker) before a `shot`.
- Opening the Settings modal by `click` on `##settings` did not work while another floating window (Light) was open; close it first. With it closed, `move` onto the gear and a `click` by `xy` (about `[53, 1840]` at 3334 px wide) opened it.
- Picking a card then `Open##drawer` is more reliable than a double click when a hairstyle must be chosen first.
- Do not leave the Light window open for later shots (its close button has no label; click its X by `xy`, or toggle View > Light settings).

Existing scripts: `tests/ui/picker_editor.json` (picker filters, drawer, hairstyles, editor style switcher), `tests/ui/editor_full.json` (every inspector section, both bars, view / tool / camera / light keys, menus, settings, shortcuts, export), `tests/ui/bone_stiffness.json` (needs `--cfg guillaume_l124_locks_hug`). The manual's screenshots were made with a script of this kind (`docs/guide/img/`).

Run recipe from an agent: write the script under a scratch folder, set `"out"` there, run the exe in the foreground with a timeout (the process exits by itself), then read `ui_test_result.json` and look at every PNG before using it.

## Export

UI: Export section (`Export edits + mod`, `Export for release (requires Core)`); agent: `{"do": "export", "tag": ..., "mod": ..., "release": ...}`. Both call `exportAll`, which writes `<tag>_edits.json`, `_look.json`, `_geo.json` and runs `desk_export.py`:

```
py desktop_studio\tools\desk_export.py --cfg <cfg> --edits <x_edits.json> --look <x_look.json> --geo <x_geo.json> --mod <modName> --tag <tag> [--limit 1.2] [--stiffness <map.png>] [--density-png <p>] [--colour-png <p>] [--release]
```

- `--mod` must start with `mod` and use letters, digits and `_` only. The export is **blocked** when the budget ratio in `_geo.json` exceeds `--limit` (default 1.2) (agent exit code 6).
- Output: `build\desktop_studio\<cfg>\export\`: `<char>_<tag>_edits.json`, `_look.json`, `_geo.json`, `_config.json` (a pipeline config proposal with `edits` and `look.extra_set`; rename it to a new `<char>_l<round>_<tag>` and copy the edits to `tools\hairworks\edits\` to build it with HairLab; with `--release` it carries `"core": true`), `<mod>\content\blob0.bundle` + `metadata.store`, `INSTALL_INSTRUCTIONS.txt`, and `<mod>_<tag>.zip`. Non-default hairstyles use `<char>_<style>_<tag>_...` names.
- It starts from the character's OWN built redfur: geometry is rewritten only when there are ops, look values only when they differ from the build, stiffness map only when painted (opt-in, preview not verified in game). Physics, LOD, density mask and collision stay as built.
- **Release export** (`--release`): the same self-contained mod plus `content\scripts\local\hwfa_req_<mod>_<crc>.ws` (calls `HairworkForAllCore_Required_GetItFromNexus13996()` and `HairworkForAllCore_v1_0()`), `REQUIREMENTS.txt`, `hairworkforall_mod.json` (`requires_core`, and the Graphics Control requirement with "Hair root transparency mode" = 0), and requirement lines in `INSTALL_INSTRUCTIONS.txt`. Without the Core installed the game's script compiler fails with `Could not find function 'HairworkForAllCore_Required_GetItFromNexus13996'`. The Core state is read from `<game>\mods\mod0000HairworkForAllCore\content\scripts\local\hairworkforall_core.ws` plus `version.json`, against `CORE_VERSION` in `core/hwcore.py`; see `core/README.md`.
- **Beard edits** (Beard mode): when the beard fur has ops or look changes, `exportAll` also writes `<tag>_beard_edits.json`, `_beard_look.json`, `_beard_geo.json` and passes `--beard-edits / --beard-look / --beard-geo`. The beard fur of the build (`beard_fur.fur_path` of the pack) is always written at its own in-game entry (`hb_*.redfur`), edited when those args are given; the hair goes to the entry matching the pack's `comp`. Beard budget: checked against the beard as built (`<cfg> beard (as built)`); short guides (< 5 mm stubble) are only a warning, zero-segment / duplicate / tiny-face counts block only when worse than the beard as built. The beard stiffness map is not exported.
- Nothing is installed. To test in game, copy the mod folder into `<game>\mods` through the repo's build scripts (HairLab `install`), never by hand-swapping `metadata.store` or `blob0.bundle` (a hand-swapped `metadata.store` once broke all game text).

## Approved-build rules for Studio changes

- `desk_prep` rebuilds of every approved config must stay **byte-identical** to `mods\mod<Char>Hairworks` (checked 2026-10-11 for Guillaume, c04ma, Regis, Dandelion, Triss, Keira; Vesemir `vesemir_r31a`). Run the check after touching `hairpipe.py`, `redfur.py`, `strand_edits.py` or `desk_prep.py`.
- New op types or keys are opt-in and appear in an edits / config file only when used (example: `reshape` for baked curls, the painted stiffness texture).
- Keep `tools/hairworks/strand_edits.py check <edits> build\hairbatch\edit\<cfg>.json` passing for edits the Studio exports.
- Update `desktop_studio/README.md`, and `tools/hairworks/HAIRWORK.md` in the same commit as a behaviour change.

## MCP server (live session)

`desktop_studio/mcp/hairwork_studio_mcp.py` exposes a live, hidden Studio session as MCP tools (stdio, no third-party packages; Pillow optional for crops / sheets). It starts `HairworkStudio.exe --serve [--out <dir>]` (no window, no input; log `build\desktop_studio\serve.log`): one JSON command per line on stdin, one `@@HWS {json}` reply line on stdout. Every `--agent` step is a command, plus `open`, `status`, `shots_list`, `render` (shot / view / eye+target+fovy, `overlay` none|scalp|mask|guides), `guides`, `guide`, `faces`, `densify`, `root_to_scalp`, `apply` (generic op on selected guides), `pick_region`, `undo`, `redo`, `reset_edits`, `look_get`, `materials_list`, `save_edits`, `quit`. Any command takes `"baseline": true` to run on the build as opened.

Register (release zip, `<studio>` = the unzipped folder; the same `desktop_studio\mcp\` path exists in a repo clone, where you use `py` instead of the bundled python): `claude mcp add hairwork-studio -- <studio>\python\python.exe <studio>\desktop_studio\mcp\hairwork_studio_mcp.py`. `HAIRWORK_STUDIO_EXE` overrides the exe, `HWS_OUT` the output folder, `HWFA_GAME` the game folder. **Start with the agent skill `docs/agents/SKILL.md`** (setup checklist, rules, the loop, tool list; `.claude/skills/hairwork-studio/SKILL.md` in the repo) and the starter prompt in the README. From 0.2.1 the server and `hws.py` ship in the release zip and the public repo; `autotune_*.py` are internal and not shipped (text below about the auto-tuner is history). Loop: `studio_open` -> `studio_compare` (vanilla | as opened | current [+ scalp]) -> `studio_render overlay=scalp` / `studio_scalp_coverage region=..` -> `studio_pick` / `studio_pick_region` -> `studio_densify` / `studio_duplicate` / `studio_move_root_to_scalp` / `studio_delete` (`show: true` returns the render) -> `studio_scalp_coverage` again -> `studio_save` under a new name. Outputs go to `build\desktop_studio\mcp\`. Approved builds are never written.

**Beard mode** (`studio_fur {"fur": "beard"}`, serve / agent step `fur`): on builds with a beard fur (`studio_status` shows `has_beard: true`; Zoltan `zoltan_l292_b`, Lambert beard configs), every following tool, look / material / stiffness change, check and the budget act on the beard; the hair stays visible as the preview. `studio_fur {"fur": "hair"}` switches back. Each fur keeps its own ops, undo history and look. `studio_save` stores the beard under the project key `beard` (`ops`, `look`, `material`, `keep_colours`, `stiffness`, `collision_r`; the top-level keys stay the hair, so old projects load unchanged) and `"fur": "beard"` when saved in Beard mode, which reopens in Beard mode. Export writes both furs (see Export).

**Guide views** (2026-10-14): `studio_guide_view` (serve `guide_view`) sets the two guide display filters of the app: `front` (front layer only: guides not hidden behind other hair from the camera), `body` (guide parts behind the head / body / clothes not drawn), `front_pct` (10-100, default 50: share of a guide's body-visible points that must be in the front layer), `tol_mm` (1-40, default 12: depth tolerance), `select_visible` (default true: brush / box / click select only visible guides). With camera keys (`shot` / `view` / `eye`+`target`+`fovy`) it computes the visible set for that camera and returns `alive`, `shown`, `in_rect`, `clipped_by_body`, `ms`, `ms_parts`, `body_tris`, `buffer_px`; `guides: true` (+ `limit`) lists the indices, `select: true` makes them the selection, `rect: [x,y,w,h]` (pixels of the render size) keeps only guides with a visible point inside. `studio_render` takes `guides_front` / `guides_body` (with `overlay: "guides"`) as one-render overrides and returns `guides_shown`. Works in Beard mode (acts on the edited fur). Use it to pick the outer layer of a style (`front: true, select: true`) before a comb / curl tool, so the inner layers are not touched.

Scalp overlay area: only the head mesh's scalp is green, taken from the painted short scalp hair in the head diffuse (dark texels, mesh-connected to the head top, above the head centre; `computeHeadScalp` in `agent.cpp`). All other skin (face, forehead below the hairline, ears, neck, body) is flat grey, so green pixels = scalp that should be covered by hair. It does not use guide roots (they can sit inside the forehead).

Hairline tools (serve / MCP): `hairline_check` (roots on skin outside the painted scalp with `to_hairline_mm`, flow outliers = root direction > `max_angle_deg` off the 8 nearest guides; with a camera a marked render: magenta painted hairline, red roots off scalp, yellow flow outliers), `align_to_hairline` (carry off-scalp roots onto the painted hairline, `inset_mm` inside; `force` for every selected root), `flow_comb` (turn the root part around the scalp normal toward `away_from` a parting line [[p0],[p1]], a `direction`, or the neighbours' mean; `strength`, `span`, `min_angle_deg`). `render` takes `"hair": false` to see the scalp mask itself. The scalp mask is per head-mesh vertex (about 1 cm apart), so treat `to_hairline_mm` under ~8 mm as on the line.

Bald spots and partings, the recipe that worked on Guillaume (`guillaume_mcp_3`):
1. `studio_render` from a top camera (`eye [0,0.45,2.25] target [0,0,1.86] fovy 22`) with `overlay: "scalp"` to see where scalp shows; `studio_pick` two or three points along a parting (`scalp_edit` = edit-frame point).
2. `studio_plant_parting` with that line (defaults: one row 4 mm out each side, every 6 mm, root part turned away from the line and lying on the scalp).
3. Frizz: `studio_lay_down` (`max_length` 0.25) bends lifted root parts onto the scalp along the local flow. Do NOT delete short guides first: they usually hold the scalp coverage (deleting 5 opened 543 -> 4406 px). `studio_hairline_check` with `parting` lists `lifted` guides and keeps parting crossings out of the flow outliers.
4. `studio_fill_scalp` from the top camera (and the shot that still shows green), 2–3 passes, re-measuring `studio_scalp_coverage` each time; stop when it stops dropping. Watch the budget ratio (<= 1.2).
5. `studio_compare` (shots 15, 4, 3, `crop: "top"`, `scalp: true`) against vanilla.
`flow_comb` and `align_to_hairline` now only move the root part (`span_mm` / `fade_mm`); the old whole-strand behaviour threw long hair across the face.

**`studio_rebuild_from_cards` (2026-10-12, opt-in, Studio-only): delete and re-trace the guides from the vanilla cards.** For builds that look nothing like vanilla (too few / wrong guides). It reuses the ideas of `tools/hairworks/growth.py` (`card_lanes` -> `chain_segments` -> `visible_card_points` -> `sample_scalp` -> `guides` -> `hug` -> `faces_for`): lanes = iso-u lines along each card UV island's root -> tip direction (root = the v end nearer the scalp), one lane per overlapping UV copy (mirrored halves), trimmed where the card alpha shows no hair; segmented cards are chained end to end; stacked duplicate lanes (within `dedupe_mm` 3) dropped. Roots = Poisson points (`spacing_mm`, or `count`, or by default the spacing that gives the hair budget of the build as opened, `budget_target` 1.0) on the PAINTED scalp (`scalp_only`, never the forehead under a fringe) within `reach_mm` of visible near-skin card hair; each root follows a card lane passing within `near_mm` (balanced pick weighted by remaining length and by `root_bias_mm` 40 = prefers lanes that start near the root); roots with no lane copy the nearest traced guide (`copy_mm`). `hug` 0.35 presses the near-skin layer onto the scalp (1 = card distance kept); strands through the head (pushOut) or within `eye_mm` (10) of an eyeball are rejected. New growth faces = Delaunay of the roots in the polar map (`edge_mm` 34 / circumradius limits); kept old guides (with a `where`) are stitched in. Builds with a density map get ONE flat growth uv at the build's mean density for all new guides (`uv_mode` "uniform"; per-guide uvs across card gaps gave patchy bald spots; "nearest" = uv of the closest old face). Spacing is raised until the budget ratio is <= the limit unless `ignore_budget`. `where` (back / front / left / right / z_min / z_max / near+radius on the ROOT) limits it; `replace: false` adds between the existing guides. One undoable op `{"op":"rebuild", "delete", "guides", "base", "uv", "faces"}` (groom.cpp `applyRebuild`), saved in projects; the HairLab pipeline (`strand_edits.py`) does not know it, so it lives in Studio projects / Studio exports only.

**`studio_hairline_fill` (2026-10-12, opt-in, Studio-only): fuller, cleaner hairline (front, temples, around the ears) from GUIDES only.** Background: the earlier Lambert hairline work (L73 `hairline_cards`) kept a band of vanilla card triangles along the hairline under the strands; it looked fine at the top front but the card band clashed with the strands at the sides (hard dark slab at the temples on Sheala, "SAME" on Lambert) and the user dropped it ("they stick out"). This tool adds no cards. Along the painted hairline (or the vanilla card footprint edge: `scalpMesh` falls back to it) it takes stations every `spacing_mm` (5) in `part` (`all` | `front` | `left_temple` | `right_temple` | `temples` | `ears` | `sides`; azimuth around the skull centre, 75 mm behind the eyes: front <= 32 deg, temples <= 68, ears <= 125, nothing below eye - 7 cm) and plants `rows` (2, max 4) at `offsets_mm` ([2,5,8,11], first `rows` used) inside the line. Each new guide is the nearest guide of length >= `min_length` (0.06; 0.03 for short hair) within `template_mm` (25; 40 works better) on the SAME side, copied by ROTATION about the skull centre (a translation down the side made the copies flare out - first Lambert test), shortened toward the edge (`taper` 0.6 = outer-row length factor), root part hugging the scalp (`lift_mm` 2, `span_mm` 25). Rejected: copies through the head, standing more than `tuft_mm` 12 off the skull in the first 40 mm, in front of the face below brow + `brow_clear_mm`, on the ear box or in the column in front of / over the ear (root included, both frames), roots within `covered_mm` (0.6 x spacing) of an existing or new guide. Growth faces: the duplicates carry `"edge_face": true`, so a root past the open edge of the growth mesh gets 1-2 new faces fanned onto the nearest open edges (outer side only, UV = edge midpoint) instead of folding the nearest face; inner rows are planted first so the outer rows attach to them (`edge_faces: false` = old split only). `straighten: true` places stations on a smoothed line (local mean over `smooth_mm` 12). Budget: refuses when the ratio is already above `max_ratio` (1.2) and drops the outermost new guides until it is under. `list_only` (or `dry_run`) reports `planned` roots / per-part counts / rejection counters (plus `hairline_points`, `skull_c`, `ear_boxes`).

- `studio_free_budget`: makes room when the budget ratio is pinned at 1.2. Islands whose ends differ by `orient_margin_mm` (15) in skin distance vote per u bucket (8). Ambiguous islands take their bucket's vote, else the mesh vote. Chains orient by majority. Report: `islands_reoriented_by_vote` (Fringilla 468, Ves 477, Tamara 267, Shani 13, Anna / Crach 3).
- `trace: "flow"` (default `lane`): each new root traces a streamline through the card flow field instead of copying one lane. Start = the lane tangents in the column above the root, clustered twice (two opposite flows at a parting do not average out). Each step (`flow_step_mm` 3) gathers lane points within `flow_radius_mm` (10) that go the same way, with `flow_inertia` 0.35. Length = the picked lane's remaining length x `flow_length_scale`. With `flow_tip_stop` (true) the strand ends where the lanes around it end (no tails past the card tips). Near the head it holds a per-root share (`flow_layer_min` 0.35 .. `flow_layer_max` 1.15, hashed) of the local card height, rising over `flow_rise_mm` (25), with strength `flow_hold` (0.5). `flow_face_full` (true): off the painted scalp the strand holds the full card height, at least `flow_clear_mm` (5). `flow_start: "lane"` + `flow_start_mix` start along the picked lane instead. Failed traces fall back to a neighbour copy (`flow_failed_to_copy`). Flow gives volume, layering and the swept shapes that the lane copy flattens: Shani's side sweep, Tamara's forward fringe, Ves's fringe, Fringilla's volume. It is WRONG for long straight hair over the face (Eredin: a dark streaky smudge on the temple / cheek in front of the ear stayed with every flow setting; the lane trace has none) and for Crach / Anna (flow follows the fur / curl cards into long tails).
- `flow_whorl` (0 = off; 0.4 used) + `flow_whorl_agree` (0.55): at a whorl or parting every strand leaves the centre and the scalp shows (Ves's crown hole in v1 and in every flow try, Tamara's back). Roots whose start tangents agree less than `flow_whorl_agree` (|sum w t| / sum w) start AGAINST the flow for this share (hashed): they cross the centre, then follow the far side's flow. Report: `whorl_crossed`. Ves's crown hole shrank to a small vanilla-like whorl. Fringilla's front parting patch stayed (agree 0.65 made no difference).
- `density_mode: "coverage"` (default `budget`): root spacing from the visible card hair instead of the budget. Card samples with alpha > `alpha_tip` are weighed by alpha. Coverage at a skin point = the weights in its column (`coverage_radius_mm` 10) / column area. Poisson spacing = `coverage_spacing_mm` (7) / sqrt(clamp(cov / `coverage_ref` 1, `coverage_floor` 0.25, 1)). Roots with cov < `coverage_min` (0.08) are dropped. Spacing rises only when an explicit `budget_target` is exceeded. Eredin: budget ratio 0.08-0.15 (v1 0.9 = the heavy curtain).
- Root zones (`exclude_ears` + `ear_pad_mm` 10 and the r3 ear box keys `ear_lat_mm` / `ear_top_mm` / `ear_box`; `exclude_temples_mm` = below eye level + this, outside the eyes' width, in front of the ear). `ear_route` behind (default) | drop | none moves or drops new strands that cross an ear (r3 routeBehindEars). `ear_faces` (true with exclude_ears): a growth face is dropped when its centroid strand or one of its 3 edge-middle strands crosses an ear (HairWorks interpolates hair across the face). Report: `candidates_excluded_zones`, `ear_routed`, `ear_dropped`, `ear_faces_dropped`, `ear_boxes`.
- `scalp_grow_mm` (0) + `grow_card_mm` (8): roots may also sit up to this far off the painted scalp when visible card hair lies within `grow_card_mm` (never on the front forehead). Fringilla's painted scalp is small (25519 candidates on it vs 23020 off it). `eye_mode: "cut"` (default reject) cuts a strand before its first point within `eye_mm` of an eye instead of rejecting it (`eye_cut`).

  - Eredin: `{"layer":"inner","density_mode":"coverage","exclude_ears":true,"ear_lat_mm":30,"exclude_temples_mm":60,"orient":"vote"}` (lane trace).
  - Fringilla: F + `orient vote, eye_mode cut, scalp_grow_mm 15, flow_whorl 0.4, exclude_ears`.

  - Tamara: F with `flow_layer_max` 0.85 + `orient vote, flow_whorl 0.4, exclude_ears` (without exclude_ears the flow hair covered her ear and the second opinion rated it worse than v1).
  - Ves: F + `flow_whorl 0.4`.
  - Crach: `{"budget_target":0.9,"layer":"inner","hug":0,"offset_keep":1,"exclude_ears":true,"orient":"vote"}` (the full card offset gives volume under the head band; ears free). Flow on Crach grew long tails down the back.

**`studio_rebuild_from_cards` rebase v3 modes (2026-10-13, opt-in, Studio-only; outputs `build\desktop_studio\mcp\rebase3\<char>_rb3\` + `rebase3_gallery.html`).** Without the new keys nothing changes (the Ves v2 recipe re-renders the v2 project to < 0.001 / 255 mean pixel difference at 3/4, back, top).
- `part_detect` (+ `part_band_mm` 18, `part_depth_mm` 70, `part_min_flow` 0.25, `part_extend_mm` 10, `part_debug`): the part line = per 1 cm front-to-back row of the top, the x where the sideways component of the card flow turns from -x to +x (gaps of up to 20 mm without card data are bridged, the longest smooth run of rows is kept). Report: `part_rows`, `part_line_rows`. Roots within the band grow even without card hair straight above them (`part_candidates_added`), none within `part_gap_mm`/2 (3) of the line. Flow trace: band roots start combed AWAY from the line (`part_comb` 0.7, `part_layer` 1.0, held `part_clear_mm` 4 off the skin), no whorl crossing; lane trace: only lanes leaving the line. `part_split` (default true) drops growth faces across the line. LESSON: combing away WIDENS the bare patch (Ves top scalp pixels 13.9k -> 25.7k), so do the opposite: `part_cross_mm` (0 = off) makes the band roots this close to the line cross it and follow the far side (the line is covered): Ves `part_cross_mm` 18, `part_extend_mm` 30, `part_split` false (front patch 739 -> 13 px, top 13.9k -> 6.7k).
- `fringe` (+ `fringe_reach_mm` 20, `fringe_clear_mm` 3, `fringe_drop_mm` 10, `fringe_front_mm` 25, `fringe_root_back_mm` 40): fringe lanes = tip at least `fringe_front_mm` in front of the head centre, `fringe_drop_mm` below the lane root, off the painted scalp, root not more than `fringe_root_back_mm` behind the centre (Ves's fringe cards start at the part, behind the centre). Roots within `fringe_reach_mm` of a fringe lane copy it (lane copy with `offset_keep`, held off the skin) instead of the flow / lane trace. Reports `fringe_lanes`, `fringe_lanes_rejected`, `fringe_strands`. Use `fringe_drop_mm` 0. A large reach bares the front where the copied strands leave (Fringilla reach 20 = bald patch; 12 + part_cross = OK).
- `alpha_density` (+ `alpha_lo` 0.15, `alpha_hi` 0.6, `alpha_radius_mm` 6): a Poisson root survives with probability smoothstep(alpha_lo, alpha_hi, mean card alpha in the column above it); fully transparent columns get no candidates. Its spot stays taken (thin, not refilled). Eredin: defaults bared the whole side; `alpha_lo` 0.03 / `alpha_hi` 0.3 removed the temple smudge and gave a ragged hairline but still shows a scalp band above the ear.
- `clump_var` 0..1 (+ `clump_min_mm` 4, `clump_max_mm` 14, `clump_pull` 0.6, `len_var` 0.25, `fly_frac` 0.3, `fly_mm` 12): post-pass on the new strands: clumps of hashed size, member tips pulled toward the clump's centre strand (tapered points), length varied, `fly_frac` of the strands at the edge of the visible card hair drift sideways (fine flyaways) and are shortened. Reports `clumps`, `flyaways`. Helps Tamara's crown a little; on Crach it gave spiky strays above the head band, on Fringilla a crown hole.
- `nape_cut` (+ `nape_cut_mm` 0, `nape_pct` 0.05): no roots on the back half below the lowest vanilla card roots near the skin, per 16 azimuth bins (`nape_cut_z`, `nape_candidates_cut`). Crach: smoother, less clumpy nape. Anna: no visible change.
- `skin_exact`: signed distance to the nearest head triangle instead of the nearest vertex plane. Made Ves worse; not used.
- `card_color` (root / tip colour from the vanilla texture) was not implemented.
- Recipes = the v2 recipe + (each followed by `studio_outside_vanilla {"delete":true}`): Ves `part_detect, part_split false, part_cross_mm 18, part_extend_mm 30, fringe, fringe_drop_mm 0`; Fringilla the same part keys + `fringe, fringe_drop_mm 0, fringe_reach_mm 12`; Tamara `clump_var 0.5, exclude_temples_mm 40`; Crach `nape_cut`; Eredin `alpha_density, alpha_lo 0.03, alpha_hi 0.3, clump_var 0.6`; Anna `nape_cut`; Triss (no v2) `{"budget_target":0.9,"part_detect":true,"part_split":false,"part_cross_mm":18,"part_extend_mm":30}`.

**Rebase auto-tuner (2026-10-13, opt-in, Studio-only; session `tune1`, outputs `build\desktop_studio\mcp\tune1\<char>_tune\` + `tune_gallery.html`).** `desktop_studio/mcp/autotune_rebase.py <char> --cfg <cfg> --base <rb3 or rb2 recipe.json>` drives a hws daemon (set `HWS_PORT` / `HWS_SESSION`): per candidate `reset_edits` -> `rebuild_from_cards(params)` -> `outside_vanilla delete` -> 6 scalp-overlay renders (front, 34, left, right, back, top) scored against the vanilla cards from the same cameras (lower = better). Hair masks = |render with hair - render without hair| for both cards and groom. Terms: silhouette miss / outside (split background vs skin), scalp (painted scalp showing where vanilla shows none; scalp and miss_skin add the WORST view to the mean), colour, block orientation, outline roughness (frizz), eye_check, budget above 1.0, and always-on per-strand geometry: strays (root->tip direction 45 deg off all 8 neighbours), strands inside the head (`push_out list_only`), roots below the vanilla nape line (`nape_cut` probe), stiff ends (hair-mask change of the lower 45 % between rest and a 1.2 s walk, sim on minus sim off, only for hanging hair). Search <= 40: base, ~20 single-key mutations, greedy combination, numeric fine steps. Writes recipe.json (steps + breakdown + every candidate), the project and `views\`. `--score '<json>'` scores one recipe; `auto_clip` ignores vanilla card pixels below the base hair when the card mask is > 2x the base hair (Crach's fur cape is in the hair-card mesh; `--clip-margin`). Gallery: `autotune_gallery.py <dir> [verdicts.json]`.
- Optional judge, DEFAULT OFF (`--judge agy`; off = the score's pick, unchanged): for the top 5 by score + base, vanilla | candidate crops of fringe / crown / temples / nape / side ends / back go to `agy -p` (gemini-3.8-flash-medium, `--add-dir` the crop folder, prompt says use view_file; headless mode auto-denies commands, do NOT add --dangerously-skip-permissions). Narrow yes/no questions (natural strands, parting like vanilla, ends loose, scalp showing) -> veto (more defects than base) and tie-break (within 3 % loss). Output goes to a file, the agy tree is taskkilled on timeout (a piped `subprocess.run` hung 30 min). Failures fall back to the score (logged). Shani demo (`tune1_dev\shani_tune_judge`): score pick = the no-judge pick (loss 0.656), the judge swapped to an equal-loss sibling (budget 0.8, 2 fewer defects).
