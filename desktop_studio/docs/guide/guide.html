Hairwork Studio

User guide for version 0.1.0. The desktop editor that previews and edits NVIDIA HairWorks hair for The Witcher 3: Wild Hunt (5.0 next-gen), runs the real HairWorks simulation, and exports ready-to-install hair mods. Created by WinterElfeas · Hairwork for All on Nexus Mods

What it is and requirements

Hairwork Studio is a native Windows application (C++, DirectX 11) that loads a character from Hairwork for All, shows its hair rendered and simulated by the real NVIDIA HairWorks 1.2.1 runtime (gravity, stiffness, damping, collisions, wind, level of detail), lets you edit the guide strands and the material, and exports a mod folder and zip for the game. Nothing is ever installed into your game automatically.

To run the Studio

  • Windows 10 or 11, a DirectX 11 GPU.
  • The Witcher 3 (the 5.0 next-gen version) installed. The Studio reads the game's own files to build hair.
  • No Python to install. The release bundles its own private Python (the python folder next to the exe) with everything the build scripts need; it does not touch any Python you may have. Unzip the release anywhere with write access and run HairworkStudio.exe. (Only if you build the Studio from source: Python 3 with py -m pip install -r requirements.txt.)
  • The NVIDIA HairWorks runtime DLL (NvHairWorksDx11.win64.dll). The release folder bundles it next to the exe. Otherwise point Settings at your own HairWorks 1.2.1 SDK copy (see First launch).

To play a hair mod exported from the Studio

Players need two other mods.
  1. Hairwork for All – Core (Nexus mod 13996). Mods exported for release stop the game at startup without it (see Troubleshooting).
  2. Graphics Control (Nexus mod 13349) with PT hair → Hair root transparency mode set to Mode 0. In mode 1 path-traced hair shows see-through gaps.

First launch and settings

Double-click HairworkStudio.exe in the folder you extracted. A short splash shows, then the character picker. Nothing has to be loaded for the app to run.

The status bar at the bottom shows HairWorks runtime loaded when the DLL was found. Its right side shows the Core state (see Exporting): Core v1.0.0, Core missing, an outdated version, or Core incomplete.

Open Settings with the gear at the bottom of the left tool rail. Fields:

  • SDK folder: your HairWorks 1.2.1 SDK folder (it contains bin\win64\NvHairWorksDx11.win64.dll).
  • DLL: optional full path of the DLL, overrides the SDK folder.
  • Python: command used for the pipeline scripts. Leave it alone in a release: it uses the bundled python\python.exe automatically (a source build defaults to py). Only change it to use a different Python on purpose.
  • Game folder: the Witcher 3 install folder (it contains content\content0 and mods). The build scripts read the game's files from it and the Core check looks in its mods folder.

Press Save settings (restart to apply), then restart the Studio. Settings are stored in %LOCALAPPDATA%\HairworkForAll\desktop_studio.json. In a release the runtime DLL next to the exe is used; the SDK folder and DLL fields are only needed if you want a different HairWorks runtime.

The character picker

The picker opens at start and whenever you press Ctrl+O, click Characters, or click the breadcrumb in the title bar. Esc returns to the editor. The page lists named characters and generic haircuts as portrait cards, each with a status badge (Approved, Final, Pick, In progress, On hold, Not started).

Filters

  • Search (Ctrl+F): by name or by any build name (for example l124).
  • Status chips: All, Approved, Final, Pick, In progress, On hold, Not started.
  • Gender (All, Male, Female) and portraits: Painted (default), Ours (our in-game capture of the best build) and Vanilla (the unmodified character). The release ships the painted portraits; Ours and Vanilla only show pictures where in-game captures exist on your PC. The refresh button re-reads the character list.
  • Hair type: Cards (loose vanilla hair cards, the main candidates), Tied (bun, braid, ponytail), Native (the game already uses HairWorks for it), Helmet-hood, Beard only, Bald. Hide no-hair characters leaves out bald, helmet and beard-only characters.
  • Game part: Base game, Hearts of Stone, Blood and Wine.

Opening a character

Double-click a card (or hover it and click the arrow, or select it and press Enter) to open its best build: the approved one when there is one, else the current pick. A single click opens the details drawer on the right.

  • Open: opens the best build (the approved build when there is one).
  • Start from approved: starts editing from the approved build. Disabled when the character has no approved build.
  • Plain conversion: the character's base conversion, the plain starting point (thicker basic strands), to work from scratch. When it has not been built yet, the Studio builds it first (nothing is installed). A character without a base config shows Start a plain conversion · coming soon.
  • Variants: every other build of the character, newest first, with Built only to hide variants that have no fur yet. Click one to open it.
  • A character whose hair is a helmet or hood, a beard only, bald, or tied cards shows an explanation instead and nothing to open. A character the game already renders with HairWorks (Native) is shown for reference.
  • The drawer's hairstyle tabs or dropdown choose which hairstyle of the character you look at (see Hairstyle switcher). A hairstyle with no build yet says No HairWorks build yet.

The first time a build is opened the Studio prepares a data pack for it with the Python pipeline, which can take a while. Later opens are instant unless the build changed.

The editor

  • Title bar: File / Edit / View / Help menus; the centre breadcrumb shows character, hairstyle, build, status badge and the number of edits (unsaved when not saved); Characters; Save; and the amber Export mod button (disabled above the budget limit).
  • Tool rail (left): Select, Move, Comb, Curl brush, Paint stiffness, Symmetry, Undo, Redo, Duplicate, Shorten, Delete; at the bottom Shortcuts (F1) and Settings. Every control has a tooltip with its shortcut.
  • Viewport: the hair on the character, with the top and bottom floating bars, a top-left HUD (Edit pose chip, selection chip, guide / CV / face / collider counts), an axis gizmo, a tool hint card and the fps.
  • Inspector (right): character card with the build menu (switch build, open folder, reload), the budget card, then collapsible sections: Material, Look, Physics & motion, Stiffness map, Curl tools, Symmetry, Edit settings, Export. Slider rows show a tick at the build's value; double-click or Ctrl+click a value to type it; right-click a slider to reset it to the build value.
  • Status bar: status message, close-up hair count with the budget meter, simulation state, edit count, fps, Log (opens a bottom drawer), the Core state and the NVIDIA credit.

Viewport, camera, edit pose

Camera

  • Orbit: right mouse drag. Pan: middle mouse drag. Zoom: mouse wheel.
  • Top bar buttons Front, ¾, Side, Back (keys 1 2 3 4) jump to the same views the in-game comparison shots use. F frames the head. O toggles a turntable. Numpad 1 3 7 9 give front, right, back, left. F12 saves a screenshot to build\desktop_studio\screenshot.png.

The floating toolbar

Drag the toolbar by its grip dots (double-click the grip to put it back), the chevron collapses it. Amber means on.

The head and body mesh (M) and the turntable (O) are in the View menu.

View → Scalp highlight (green) paints the head and body skin flat, unlit pure green while the hair stays normal: any green you still see through the hair is bare scalp, so thin spots and parting gaps are easy to find. Switch it off to go back to the normal look.

Playback bar and motion

The bottom bar has play / pause (Space), stop and reset to rest (Esc; when something is selected the first Esc clears the selection), step one frame (.), the motion preset, speed, amount, and wind (J) with its strength. R re-teleports the simulation if the hair got tangled.

Motions move the head, neck and body bones, so inertia, sag and swing show as in the game.

Edit pose

Editing tools (Move, Comb, Curl, Paint) pause the motion and edit the hair at the bind pose, shown by the Edit pose chip at the top left (Tab toggles it, Resume restores the motion). The Select tool keeps the motion running. Edit while moving (Physics & motion) lets you edit the posed, moving hair; the edits are converted back to rest space.

Selecting and editing guides

Hair is edited through its guides, the strands the simulation drives; the thousands of rendered hairs follow them.

ToolKeyHow it works
SelectQClick a guide, anywhere along its strand (not only on its points); Ctrl+click toggles, Shift+click adds; drag on empty space for a box selection. Esc clears.
MoveWDrag the selected guides (a single guide under the cursor is picked automatically). With exactly one guide selected, dragging one of its points moves only that point; the neighbouring points follow softly. The move falloff is set in Edit settings.
CombEDrag over the hair to drag the guides under the brush; strength falls off with distance from the cursor.
Curl brushTPaint over guides; on release the curl settings are applied to everything you touched.
Paint stiffnessPPaint stiffness values on guides (see Stiffness map).

The selected guide is drawn bold blue with a yellow marker on each control point, so you can see what you are about to move. View → Scalp highlight (green) paints the visible scalp skin green, to check that roots and strands sit on the scalp.

Commands on the current selection:

  • Duplicate (D): adds a copy of each selected guide beside it (distance = Dup step mm). Useful to fill bald spots and thicken a lock.
  • Shorten (S): keeps the first Keep % of each strand's length.
  • Delete (Del): removes the selected guides.
  • Curl (C): applies the Curl tools settings to the selection.
  • Undo / Redo (Ctrl+Z / Ctrl+Y). Edit → Select all selects every guide.

Edit settings (inspector): move falloff (carry = the whole strand moves; linear = root fixed, tip moves fully; tip = mostly the lower part), From CV (control vertices before this one stay fixed), Comb strength, Keep %, Dup step mm. The brush radius (Brush px) is in the Stiffness map section and is shared by comb, curl and paint.

Curl tools and symmetry

Curl tools reshape selected guides while keeping their segment lengths. Three modes:

  • ringlet: a helix around the strand (vertical curls). Radius, turns, start, ramp, handedness, jitter.
  • roll: the ends roll under or out around a horizontal axis. Extra: shrink (spirals inwards), roll outward, and band (nape roll) where every guide rolls in the same vertical front-back plane. More than one turn loops on itself.
  • wave: a planar sine wave or a zigzag.

A warning shows when a curl gets fewer than 6 control vertices per turn: lower the turns or start earlier. Curl selection (C) applies it; Hold curls in the simulation raises the stiffness values and flattens the curves so HairWorks keeps the curled rest shape instead of letting it straighten under gravity.

Symmetry

  • Live symmetry (X, or the rail button): every move, comb, curl or paint stroke is mirrored onto the partner guides on the other side (nearest mirrored root within 15 mm; ringlets flip handedness).
  • Mirror side (also in the Edit menu): rebuilds one side from the other. Choose which side is the source, a centre band (guides near the middle stay as they are) and keep the back (leaves a tie or bun at the back untouched). The mid-plane is detected from the head mesh.

Material, look and colour

Material presets

A preset sets the strand shading and shape (width, clumping, waves, specular, glint, diffuse). Density and the density map always stay the character's. The tiles shown first are the character's current look, then the preset families:

Keep the character's colours (on by default) keeps root, tip and specular colour and the texture brightness when you switch presets. Save preset stores your current values as a custom preset (in the presets folder of the Studio) that then appears as a tile.

Look

The Look section lists the individual values grouped by Volume, Clump / wave and Colour (root and tip colour and their weight, specular colours and powers, glint, shadow, texture brightness). Colour rows edit the colour. The section summary shows how many values differ from the build; only changed values are exported.

Physics, stiffness and motion

  • Physics & motion: stiffness, root stiffness, tip stiffness, bend stiffness, stiffness strength, stiffness damping, interaction stiffness, damping, mass scale, inertia limit, back stop radius, wind scaler and wind noise. Below them a curve editor (tabs Stiffness, Bend, Strength, Damping) edits each curve from root to tip.
  • Simulate: off shows the rest pose that you edit. Close-up LOD forces the close-up (dialogue) hair count at any distance, the worst case for the budget. Edit while moving: see Edit pose.
  • W3 bone stiffness (only on hair that uses the game's extra bone-distance stiffness): the HairWorks 1.2.1 runtime does not have this game-only block, so the Studio emulates it for the preview so curls hold as they do in the game. 1 (default) = emulation on, 0 = raw runtime. Preview only; it is not exported.

Stiffness map

Paint stiffness by region: choose what the Paint tool writes (stiffness + root stiffness, stiffness only, root stiffness only), the values, and the brush size, then paint on the hair with the Paint tool (P). Low values make hair floppy there, high values stiff. Fill all with value and Clear map are there too. The map is exported only when painted.

Not verified in game yet. Painted stiffness maps are previewed live in the Studio, but a first in-game test should confirm the game reads the texture.

Budget and LOD

The budget card at the top of the inspector compares the hair cost (hair count in close-up times control points times width) with the character's approved build (or the loaded build when there is none). The bar shows 100 % at the reference tick and a 120 % limit. Hard caps are always enforced: density at most 1.2 × the reference, close-up density at most the smaller of 1.2 × the reference and 2, width at most 1.5 × the reference, LOD always on.

  • Above 120 % the Export buttons are disabled and the exporter refuses too.
  • Hairs is the estimate, Live (SDK) is what HairWorks currently draws on screen, LOD is the current detail factor.

Lighting, time of day, shadows

The Studio approximates the game's path-traced hair in real time: sun shadows, hair self-shadowing, sky light and bounce, soft occlusion. The top bar's time of day dropdown (L cycles) offers: HairLab capture rig (default, fitted to in-game frames: use it to compare with the game), Noon sun, Morning, Dawn, Dusk, Overcast, Moonlight, Torch / interior, Night. Shadows are toggled with K.

Advanced... (or View → Light settings) opens the floating Light window: lighting quality (Fast: sun shadow only; Balanced: 8 sky-occlusion maps; High: 16, default), hair view (debug visualisations, F6 cycles), time of day, a sun azimuth dial and elevation arc (drag the amber dot), shadows, sky backdrop and the individual intensity and calibration sliders. In the viewport, Ctrl + right drag rotates the sun live.

Hairstyle switcher

Some characters have several hairstyles (for example Geralt, with eight; Guillaume has just Default). In the editor the hairstyle is shown in the breadcrumb and in the inspector's Hairstyle row. Click it, or press Ctrl+Shift+H, to open the dropdown.

  • Choosing a style that has a build opens its best build. If you have unsaved edits the Studio first asks Save, Discard or Cancel.
  • A style with no build yet shows a small panel in the inspector instead (Start plain conversion when possible, else Not started yet); the loaded build stays untouched.
  • A character with a single hairstyle shows Default (disabled).

Saving projects

File → Save project (Ctrl+S) writes a *.groomproj.json file with the build, all edit operations, look changes, material, stiffness map, motion and camera, by default to build\desktop_studio\projects\<build>.groomproj.json. Save project as... chooses a path. File → Open project... (also on the start screen) loads one. The title bar shows how many edits are unsaved. The picker's right-hand panel lists your recent builds and exports.

Exporting a mod

Open the Export section from the inspector, or click the amber Export mod button.

  • mod folder: the game mod folder name (starts with mod, for example modGuillaumeHairworks). tag: names this edit set in the file names (for example desk1).
  • Export edits + mod (the dev export): for your own testing. It has no Core check.
  • Export for release (requires Core): for publishing. Same hair and textures, plus a small script that calls the Hairwork for All Core, so the game refuses to start without it.

What gets written

Everything goes to build\desktop_studio\<build>\export\ (use Open export folder). Nothing is installed into your game.

  • <mod>\content\blob0.bundle and metadata.store: the hair, built from the character's own fur so physics, LOD, density mask and collision are kept (only what you changed is rewritten).
  • <mod>_<tag>.zip: the ready mod folder in a zip, with INSTALL_INSTRUCTIONS.txt.
  • <char>_<tag>_edits.json, _look.json, _geo.json, _config.json: your edits, the changed look values, the geometry and a build configuration proposal.
  • Release export only: content\scripts\local\hwfa_req_<mod>_<crc>.ws (the requirement script), REQUIREMENTS.txt, hairworkforall_mod.json (requires_core), and the requirement lines in INSTALL_INSTRUCTIONS.txt.

Install and test in game

  1. Install Hairwork for All – Core (Nexus 13996) and Graphics Control with Hair root transparency mode = 0.
  2. Copy the exported mod folder (modXxxHairworks) into <game>\mods\, as INSTALL_INSTRUCTIONS.txt says. If you replace an existing hair mod of the same character, remove the old folder first.
  3. If another mod changes the same character's hair (for example a lore-friendly hair mod), the HairWorks mod must load first: name its folder so it sorts before the other mod (for example mod000_TrissHairworks).
  4. Start the game. If the Core is missing the game stops with a script compile error (see below).

The Studio checks the Core every few seconds in <game>\mods\mod0000HairworkForAllCore and shows its state in the status bar and in the Export section. A release export still works without the Core installed; only testing it in the game needs it.

Budget: export is disabled above 120 % of the approved build. See Budget and LOD.

Community packs

The title bar has three big buttons: the green Open User Guide (opens this guide in your default web browser), the blue Community (opens the Community window) and the amber Export mod.

A pack is a hair edit you can share: the list of edit operations made on a character, never a game file. Rules: packs contain edit operations only, never game files or NVIDIA SDK files. Browsing and applying packs needs no account; publishing needs a GitHub account.

Source and Browse

The source chip with the gear (top right) chooses where packs come from: a Local folder or a GitHub repo (with a channel, for example main). Refresh reloads the list. On the Browse tab, use the search box (name, author, tag or character) and the character chips to filter. Each card shows a preview, version, author, tags and a description, and one main button:

  • Install downloads the pack (read-only copy). Apply to groom applies it to the loaded character. Update appears when a newer version exists.
  • The ... menu: Reinstall, Create working copy (an editable copy in My packs) and Pin version (stay on this version).
  • Applying is one undo step: Ctrl+Z removes the whole pack.

My packs

  • Export current project as pack (New pack): fill in the form to turn your edits on the loaded project into a pack.
  • Each of your packs is a card with a preview: Apply to groom; Sync with upstream (merges changes of the original pack; on a conflict a dialog asks keep mine, take theirs or keep both); Update from project (re-exports the current project into the pack and refreshes the preview); Open folder; Publish....

GitHub and publishing

Publishing uses the GitHub CLI. The GitHub tab shows its state: Install GitHub CLI if missing, Sign in if not signed in, then choose the pack and press Publish. Publish opens a pull request on the community repo (set it in the source settings); nothing is sent until you press it. The Pull requests list shows the status of what you published.

What a pack carries

Every guide edit: move (including single point moves), comb, curl, shorten, duplicate, delete, mirrors (stored as resolved edits), deleted faces (found again by base-mesh index, with a check that the base mesh matches), and a rebuild from cards (stored as parameters, not as geometry).

Troubleshooting

"HairWorks runtime not found" in the status bar, or the viewport stays empty

The Studio could not load NvHairWorksDx11.win64.dll. Open Settings and set the SDK folder (or DLL), save, restart. The line runtime: ... in Settings shows the path that is tried. In a release folder the DLL must sit next to the exe.

Python or pipeline errors when opening a character

In a release the bundled Python is used, so there is nothing to install: check that the python folder next to the exe is complete (unzip the whole package again if not) and that the Python field in Settings is untouched. In a source build make sure py -m pip install -r requirements.txt was run. The Log drawer (status bar) shows the error output.

The hair has see-through gaps in the game

Install Graphics Control (Nexus 13349) and set PT hair → Hair root transparency mode to 0. In mode 1 path-traced hair shows see-through gaps. The Studio viewport does not show this problem; it only occurs in the game.

The game does not start and the script log says it could not find a function

The Hairwork for All Core is missing or too old. The game's script compiler reports:

Could not find function 'HairworkForAllCore_Required_GetItFromNexus13996'

The function name points at the Nexus page of the Core, mod 13996. Install the Core (mod0000HairworkForAllCore in <game>\mods), or remove the release hair mod. In the Studio the status bar shows Core missing or Core v<x> < <required> and Core incomplete means the script or version.json is absent.

Export buttons are disabled

The hair is above 120 % of the approved build's budget. Delete or shorten guides, lower the density or width, then retry.

Hair looks different from the game

Use the HairLab capture rig time of day, which is fitted to in-game captures, and the 3/4 or side views for comparison. The game's own light, weather and the Graphics Control settings still change how the hair looks.

The Studio crashes

The log is build\desktop_studio\desktop_studio.log inside the Studio folder (also shown in the Log drawer); the line starting with CRASH names the function and source line. Include it in a bug report.
